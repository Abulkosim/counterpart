# v0.3.0 (2026-11-18)

Two people's agents on two devices, with fewer steps and fewer ways to lose a message or a secret.

- **Pairing with a short code.** `cpart invite maya` prints `7-cider-otter@relay.host` and waits; `cpart join 7-cider-otter@relay.host sam` on the other side sets up and pairs. There is no safety code to compare: the code is checked with CPace (draft-irtf-cfrg-cpace-21, ristretto255), so the relay or anyone else gets one guess in 1.68 million. A wrong word ends the code on both sides. `--long` makes the old invite. See [docs/pairing.md](../docs/pairing.md).
- **Several relays, and moving.** An identity can use up to 8 relays, and contacts learn the list from a signed event. `cpart relay add|remove|move|list`; `move` waits until each contact has confirmed before dropping the old relay. A relay answers to several names, so a Mac and a dev container on it can use `127.0.0.1` and `host.docker.internal` for the same relay, and `cpart join` in a container finds it. See [docs/connectivity.md](../docs/connectivity.md).
- **Reconnecting.** The daemon pings quiet connections, dials again at once after the machine sleeps or the network changes, and backs off from 250 ms to 15 s. Before this, a network drop that ended at a new address left the daemon saying "connected" while nothing arrived, once for 26 minutes.
- **Replies reach a live session.** `cpart setup` installs hooks in Claude Code (as a local plugin) and Codex. A session is told when something arrives, on its next step or, in interactive Claude Code, by waking it when idle. The notice never contains the other side's text. `counterpart_follow` keeps a session on a thread until it is answered. The development flag is no longer needed.
- **The front desk answers from your repository.** `cpart share maya --repo . docs src/api` lets it read those paths from your last commit, never uncommitted or ignored files, with credentials refused and a secret scan first. Each line of a reply must cite a file and a quote, and code checks the quote is there. See [docs/front-desk.md](../docs/front-desk.md).
- **The outbound guard.** Everything your side sends is checked before it is encrypted. A secret (gitleaks rules; values from your environment, `.env`, config and credential files; never-share files; also reversed, encoded, spelled out, in pieces or across messages) is held. `cpart held`, `cpart release` (your passphrase, at a terminal), `cpart drop`. On 1,221 ordinary messages it held none. Placeholders in `.env.example` and the fixed prefix of a key (`sk_live_`) are not counted as secret. See [docs/guard.md](../docs/guard.md).
- **Two-device rig.** `scripts/devices/rig.sh` runs two Docker "devices" with live Claude sessions and puts them through sleep, network drops and relay restarts, counting what is lost.
- **Red team.** `scripts/redteam/run.sh` gives a tool-using agent planted secrets and runs 24 attacks to make it leak them, judged in code. See [docs/redteam.md](../docs/redteam.md).
- **The answering side hears about a question.** `cpart status` lists threads a contact wrote in that nobody on your side has read or answered, and the next Claude Code or Codex session you start or type in is told once. The notice carries no text from the contact, and only the first 8 characters of a thread id the contact chose.
- **A front desk that cannot run says so.** `cpart desk on` first has the daemon make one small model call and refuses with the reason and the fix if it fails. If the model fails later, the contact is told the question went to you, it shows in `cpart asks`, and `cpart status` says the desk is failing.
- **A question put only in the thread title is answered** when it has a question mark. `cpart open <name> <title> --say <text>` sends the first message with the thread.
- **Setup stops when the relay refuses you.** `cpart setup` and `cpart join` wait for the relay's answer; on a refusal they say why and what to change, and keep nothing they made.
- **The relay as a service.** `cpart relay --boot` runs the relay in the background from login (systemd or launchd), with its database in `~/.counterpart-relay`. `--no-boot` removes it.
- `cpart <command> --help` prints that command's help.
- `scripts/mac-check.sh` checks a Mac and a Docker Desktop container end to end and prints a report.
- `cpart status` shows held messages, live codes, relays and contacts you share no relay with.
