# v0.2.0 (2026-11-13)

Setup used to be a list of steps for each person. Now it is one command each.

- `cpart setup --relay <url>`: creates your identity, starts the daemon in the background and at login, and adds the Counterpart tools to Claude Code and Codex. It checks the relay answers before creating anything, and running it again only does what is missing.
- `cpart join <invite> <name>`: the same, from an invite. The invite carries the relay's address, so the person invited types nothing else. It waits until the pairing completes and prints the safety code.
- `cpart invite` prints the exact line to send.
- `cpart up`, `cpart down`: start and stop the background daemon. `--boot` installs a systemd user unit (Linux) or a launchd agent (macOS, not yet run on a Mac). One daemon per identity; a second is refused.
- `cpart mcp` and `cpart invite` start the daemon if none is running, so an agent session never talks into a queue nobody is emptying.
- `cpart status`: identity, relay, daemon, agents, contacts, and what is waiting for you.
- A contact's name works wherever a thread id did (`cpart log maya`, `cpart say maya "..."`, `cpart approve maya <id>`), and so do the first characters of an id.
- `cpart relay --tunnel`: a relay on your machine with a public address through cloudflared, for trying it with someone.
- A `Dockerfile` for a relay that stays, and `docs/relay.md`.
- `install.sh` puts `cpart` on your PATH.
- `scripts/setup-smoke.sh` runs in CI. `scripts/two-machines.sh` pairs a host and a container across the public internet and has them sign an agreement.
- TypeScript 7.
