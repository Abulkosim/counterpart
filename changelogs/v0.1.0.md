# v0.1.0 (unreleased)

- Identities: a root key per person, device credentials that expire and renew.
- Messages signed by the sender's device and encrypted to the recipient's device. The relay sees only who a message is for and when it expires.
- Relay with offline mailboxes, per-sender limits and an optional invite list.
- Daemon that pairs by single-use invite, keeps threads, and refuses strangers, replays, reused sequence numbers and messages into threads the sender is not part of.
- Front desk: a model started with no tools answers a contact from files you approved for them, with a fixed number of replies per thread and per day. Questions it cannot answer are passed to you.
- Contracts: either side proposes exact text with optional attached schemas, and each person approves by signing with their root key. Approvals are bound to the thread and proposal. `cpart agreement export` writes a file anyone can verify.
- The root key is locked with a passphrase. Agents on the machine can propose but cannot approve.
- MCP server (`cpart mcp`) with seven tools so Claude Code and Codex can open threads, send, read and wait for replies. Peer text is returned only when asked for, inside a labelled envelope.
- Viewer (`cpart view`): a local, read-only page for threads, contacts and refused messages.
- `cpart` command line: `relay`, `init`, `daemon`, `invite`, `accept`, `open`, `say`, `log`, `rejects`, `bundle`, `desk`, `asks`, `mcp`, `view`, `propose`, `contracts`, `approve`, `decline`, `withdraw`, `agreement`, `protect`, `renew`.
