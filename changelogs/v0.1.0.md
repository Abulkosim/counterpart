# v0.1.0 (2026-11-13)

- Identities: a root key per person, device credentials that expire and renew.
- Messages signed by the sender's device and encrypted to the recipient's device. The relay cannot read them.
- Relay with offline mailboxes, per-sender limits and an optional invite list.
- Daemon that pairs by single-use invite, keeps threads, and refuses strangers, replays, reused sequence numbers and messages into threads the sender is not part of.
- Front desk: a model started with no tools answers a contact from files you approved for them, with a fixed number of replies per thread and per day. Questions it cannot answer are passed to you; `cpart asks answer <id> [text]` and `cpart asks dismiss <id>` close them, and an answer with text goes to the contact as your own message.
- Contracts: either side proposes exact text with optional attached schemas, and each person approves by signing with their root key. Approvals are bound to the thread and proposal. `cpart agreement export` writes a file anyone can verify.
- The root key is locked with a passphrase. Agents on the machine can propose but cannot approve.
- MCP server (`cpart mcp`) so Claude Code and Codex can open threads, send, read and wait for replies, and propose, counter, decline and withdraw contracts. There is no tool that approves. Peer text is returned only when asked for, inside a labelled envelope.
- Viewer (`cpart view`): a local, read-only page for threads, contacts, refused messages, contracts with diffs, what needs you, and the front desk.
- Work: after an agreement, `cpart work` has a model with no tools propose the change to your repo from committed files you name. Code checks every edit and builds the patch; nothing is run and nothing is written until `cpart work apply`.
- Publish: `cpart repo init` writes the trust file, verifier and workflow for your main branch; `cpart pr` commits the reviewed work, the agreement and the bound schema on a branch and opens the pull request.
- Evidence: `cpart evidence send` tells the other side which commits, trust policy and verifier your repository has and the digest of each bound file, read from Git by code. `cpart evidence`, the viewer and `counterpart_evidence` show what your machine checked against the signed contract apart from what the other side only claims, and mark older evidence stale when the commits or policy change. `cpart pr --evidence` sends it after opening the pull request.
- Repo verifier: one dependency-free file that checks a checkout carries the schema both people signed.
- Resend on request: when messages are held because an earlier one never arrived, the daemon asks its author to send it again, and the thread recovers. Both sides limit how often this happens.
- Receipts: `cpart log` marks your own messages `(queued)` or `(at relay)` until the other daemon confirms it applied them. `--json` and the MCP tools report `received`.
- Hostile-peer suite: 112 attacks run on every commit, with a generated report in `docs/gauntlet.md`.
- `cpart` command line: `relay`, `init`, `daemon`, `invite`, `accept`, `open`, `say`, `log`, `rejects`, `bundle`, `desk`, `asks`, `mcp`, `view`, `propose`, `contracts`, `approve`, `decline`, `withdraw`, `agreement`, `protect`, `renew`, `work`, `repo`, `pr`, `evidence`.
- `scripts/frontdesk-api-check.sh`: runs the front desk against the real Anthropic API with your key. The API adapter now refuses a response that holds anything but text.
- The daemon logs each front desk run and its outcome.
- No Codex front desk: Codex cannot be started with no tools and does not report its tool calls. The reasons are in `docs/design.md`.
- `cpart mcp --notify`: an interactive Claude Code session is told when the contact's side adds something, through a Claude Code channel. The notice is a fixed template with the local contact name, ids and counts and none of the other side's text. Coalesced, at least 15 seconds apart, at most 20 an hour. Off by default. Headless sessions and Codex do not receive it.
